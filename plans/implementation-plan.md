## 1. Как пользоваться планом

План **линейный**: шаги исполняются сверху вниз, каждый шаг заканчивается зелёным `node --test` перед переходом к следующему. На каждом шаге **тесты пишутся ПЕРВЫМИ** (TDD: Red → Green → Refactor): сначала красный тест, потом минимальная реализация до зелёного, потом рефакторинг без изменения поведения. Все дизайн-решения уже приняты в роадмапе — если шаг кажется требующим нового решения, ищи ответ в указанном разделе (`roadmap.md §X` / `architecture.md` «...» / `pipeline.md` «Этап N» / `intent-vocabulary.md` «...» / `test-strategy.md` «...») и **не пере-решай**. Константы, сигнатуры и формы данных приведены в плане ровно настолько, насколько нужно для исполнения без переключения контекста; полные спецификации — по ссылкам.

#### Шаг 1.1 — `thresholds.js` + `thresholds.test.js`

**Файлы (создать):**
- `src/thresholds.js`
- `src/thresholds.test.js`

**Контракт (см. `architecture.md` «Граф зависимостей» → `thresholds.js` «только константы»; `roadmap.md` §6 «Направляющие по порогам»):**

Экспортируем константы (имена — из брифа/роадмапа, не придумывать):

| Имя | Стартовое значение | Смысл |
|-----|--------------------|-------|
| `guardMinLength` | `3` | строки короче (после trim) → guard-fail |
| `maxInputLen` | `500` | жёсткий лимит длины входа |
| `minConfidence` | `0.35` | абсолютная нижняя граница уверенности топ-намерения |
| `ambiguityGap` | `0.15` | требуемый нормализованный разрыв top1 − top2 |
| `fallbackThreshold` | `3.0` | ниже этого топ-сырого скора → запуск фаззи |
| `minTokenLenForFuzzy` | `4` | токены короче исключаются из Левенштейна |
| `domainSilenceThreshold` | `0.5` | ниже этого домен «молчит», допускается конверсационное |
| `conversationalConfidence` | `0.9` | уверенность конверсационного намерения при точном совпадении |
| `strongBigramWeight` | `3.0` | вес сильной биграммы-фразы |
| `mediumUnigramWeight` | `2.0` | вес семантически однозначного глагола/дискриминатора |
| `weakUnigramWeight` | `0.3` | вес родового/двусмысленного существительного |
| `conversationalPrecedence` | `['FAREWELL', 'THANKS', 'GREETING']` | приоритет смешанных маркеров |

Инварианты: значения — это стартовые точки (будут подстраиваться на Фазе 6); **ни один другой модуль не содержит magic numbers** (`coding-standards/SKILL.md` «Детерминизм»). Экспортировать как `Object.freeze`-объект или отдельные `const` (тест проверит заморозку — см. ниже).

**Тесты сначала (ключевые кейсы; полный список — `test-strategy.md` «`thresholds.test.js`»):**
- Все константы экспортируются и являются числами (`conversationalPrecedence` — массив строк).
- Диапазоны: `0 < guardMinLength ≤ maxInputLen`; `0 < minConfidence ≤ 1`; `0 ≤ ambiguityGap ≤ 1`; `fallbackThreshold > 0`; `minTokenLenForFuzzy ≥ 1`.
- Согласованность весов: `strongBigramWeight > mediumUnigramWeight > weakUnigramWeight`.
- `conversationalPrecedence` ровно `['FAREWELL', 'THANKS', 'GREETING']` (порядок и полнота).
- Замороженность: попытка мутации `thresholds.guardMinLength = 999` либо не меняет значение (strict mode бросает `TypeError`), либо `Object.isFrozen(...)` → `true`.

**Реализация:** один `export const THRESHOLDS = Object.freeze({ guardMinLength, ... });` ИЛИ отдельные `export const`-ы + `Object.freeze` на каждом. Выбрать одну форму и держать её во всех импортёрах. Без `Date.now`/`Math.random` (детерминизм, `roadmap.md` §4 П2).

**Команда проверки:** `node --test src/thresholds.test.js` → зелёный; затем `node --test` (весь набор) → зелёный.

**Готовность к следующему шагу:** все тесты `thresholds.test.js` проходят; константы доступны из других модулей по имени.

#### Шаг 1.2 — `normalize.js` + `normalize.test.js`

**Файлы (создать):**
- `src/normalize.js`
- `src/normalize.test.js`

**Контракт (см. `architecture.md` «Формы данных» → `normalize`; `pipeline.md` «Этап 1» + «Этап 2»; `roadmap.md` §7 шаг 3):**

```
normalize(text) → string | null
```
- Возвращает `null` (guard-сентинел), когда вход не проходит guard: не строка / `null` / `undefined` / пусто после trim / `length < guardMinLength` после trim.
- Иначе: lowercase → убрать пунктуацию (оставить буквы, цифры, пробелы) → схлопнуть серии пробелов в одиночные → trim краёв → обрезать до `maxInputLen`.
- Чистая; не мутирует вход; идемпотентна на уже чистом входе.
- **Никогда не бросает исключение** (тотальная функция; `architecture.md` «Инварианты»; `coding-standards/SKILL.md` «Производительность и безопасность»: `null`/пусто → `UNCLEAR`, не throw).

Безопасность (`pipeline.md` «Этап 2» «Ключевая логика»): все операции — одиночные линейные проходы; регулярки (если есть) — **литеральные** классы символов (например, `/[^a-zа-яё0-9\s]/g` — ReDoS-безопасный, без вложенных квантификаторов). Никакого `eval`/`new Function`.

**Тесты сначала (ключевые кейсы; полный список — `test-strategy.md` «`normalize.test.js`»):**
- Guard-fail (`=== null`): `null`, `undefined`, `''`, `'   '`, `'ок'` (короче `guardMinLength` после trim), `42` (не-строка), `{}` (не-строка).
- Lowercase: `'Приём'` → `'приём'`.
- Очистка пунктуации: `'приём,'` → `'приём'`; `'сколько стоит?!!!'` → `'сколько стоит'`.
- Схлопывание пробелов: `'а   б\tв'` → `'а б в'`.
- Trim краёв: `'  привет  '` → `'привет'`.
- Ограничение длины: вход длиннее `maxInputLen` обрезается ровно до `maxInputLen` (тест с генерацией строки длины `maxInputLen + 50`).
- Идемпотентность: `normalize(normalize('Привет,   мир!')) === normalize('Привет,   мир!')`.
- Чистота: входная строка-константа не изменилась после вызова.
- Только пунктуация (`'?!...'`) → `null` (после очистки пусто → guard-fail).

**Реализация:** импортировать `THRESHOLDS` из `./thresholds.js`; последовательность: `typeof text !== 'string'` → `null`; `trim` + проверка длины → `null`; затем lowercase, replace пунктуации, replace пробелов, trim, slice. Порядок важен (`pipeline.md` «Этап 2» «Почему здесь»): чистка до токенизации.

**Команда проверки:** `node --test src/normalize.test.js` → зелёный; `node --test` → зелёный.

**Готовность к следующему шагу:** guard работает на всех краевых входах; очищенная строка канонична (lowercase, без пунктуации, одиночные пробелы, ограничена по длине).

#### Шаг 1.3 — `tokenize.js` + `tokenize.test.js`

**Файлы (создать):**
- `src/tokenize.js`
- `src/tokenize.test.js`

**Контракт (см. `architecture.md` «Формы данных» → `tokenize`; `pipeline.md` «Этап 3»; `roadmap.md` §7 шаг 4):**

```
tokenize(normalized) → { unigrams: string[], bigrams: string[] }
```
- `unigrams`: токены по порядку (разбивкой по одиночному пробелу).
- `bigrams`: соседние пары униграмм, соединённые одиночным пробелом.
- Пустая строка → `{ unigrams: [], bigrams: [] }`; один токен → одна униграмма, `bigrams: []`; два токена → одна биграмма.
- Чистая; детерминированная; не мутирует вход.

**Инвариант из `pipeline.md` «Этап 3» «Почему здесь»:** биграммы производятся **здесь**, не в скорере/детекторе — это и есть способ ловли STT-разрывов («за писаться» становится биграммой, которая позже совпадёт со словарной записью `BOOK`).

**Тесты сначала (ключевые кейсы; полный список — `test-strategy.md` «`tokenize.test.js`»):**
- Униграммы: `'хочу за писаться'` → `['хочу', 'за', 'писаться']`.
- Биграммы: `'хочу за писаться'` → `['хочу за', 'за писаться']` (именно эта биграмма `за писаться` — критична для кейса 5).
- Пустая строка → `{ unigrams: [], bigrams: [] }`.
- Один токен: `'привет'` → `{ unigrams: ['привет'], bigrams: [] }`.
- Два токена → одна биграмма.
- Вход не мутируется (передать `Object.freeze`-строку или сравнить ссылку).
- Детерминизм: два вызова с одинаковым входом → `deepStrictEqual`.

**Реализация:** `normalized.split(' ')` после гарантии одиночных пробелов (нормализатор уже схлопнул); отфильтровать пустые элементы (страховка); биграммы — `for i in 0..n-2: unigrams[i] + ' ' + unigrams[i+1]`. Без зависимости от `thresholds.js` (чистое преобразование, `architecture.md` «Граф зависимостей»).

**Команда проверки:** `node --test src/tokenize.test.js` → зелёный; `node --test` → зелёный.

**Готовность к следующему шагу:** токены и биграммы корректны на краевых случаях; разрыв `за писаться` представлен биграммой.

#### Шаг 2.1 — `conversational.js` + `conversational.test.js`

**Файлы (создать):**
- `src/conversational.js`
- `src/conversational.test.js`

**Контракт (см. `architecture.md` «Форма экспорта `conversational.js`»; `pipeline.md` «Этап 4»; `intent-vocabulary.md` «Конверсационный словарь»; `roadmap.md` §7 шаг 5):**

```js
export const CONVERSATION = {
  GREETING: { unigrams: ['здравствуйте', 'здрасте', 'привет'], bigrams: ['добрый день', 'доброе утро', 'добрый вечер'] },
  FAREWELL: { unigrams: ['пока'], bigrams: ['до свидания', 'всего доброго', 'всего хорошего', 'до встречи'] },
  THANKS:   { unigrams: ['спасибо', 'благодарю', 'благодарность'], bigrams: ['спасибо большое', 'благодарю вас'] }
};
export const CONVERSATIONAL_PRECEDENCE = ['FAREWELL', 'THANKS', 'GREETING'];

detectConversation(tokens) → 'GREETING' | 'FAREWELL' | 'THANKS' | null
```

**Ключевая раскладка маркеров (точно по `intent-vocabulary.md` «Конверсационный словарь»):**
- **GREETING:** `здравствуйте`, `здрасте`, `добрый день`, `доброе утро`, `добрый вечер`, `привет` (однословные в `unigrams`, двухсловные в `bigrams` — распределение см. в `architecture.md` примере, главное: все 6 маркеров покрыты).
- **FAREWELL:** `до свидания`, `всего доброго`, `всего хорошего`, `до встречи`, `пока`.
- **THANKS:** `спасибо`, `спасибо большое`, `благодарю`, `благодарю вас`, `благодарность`.
- **Намеренно НЕ маркеры:** `алё`, `ало` (критично для кейса 10 → `UNCLEAR`).

**Логика `detectConversation`:** точное совпадение токенов (униграмм и биграмм) с маркерами. Если совпали маркеры нескольких классов — вернуть класс с наибольшим приоритетом по `CONVERSATIONAL_PRECEDENCE` (`FAREWELL` > `THANKS` > `GREETING`). Если ни одного — `null`. Без весов, без фаззи.

**Тесты сначала (ключевые кейсы; полный список — `test-strategy.md` «`conversational.test.js`» + инварианты `intent-vocabulary.md` «Инварианты для `conversational.test.js`»):**
- Структура `CONVERSATION`: ровно 3 класса (`GREETING`, `FAREWELL`, `THANKS`), у каждого `unigrams` и `bigrams` (массивы строк).
- Все маркеры в нижнем регистре и без пунктуации.
- `алё` и `ало` отсутствуют во всех трёх списках (отдельный `assert.ok(!allMarkers.includes('алё') && !allMarkers.includes('ало'))`).
- `CONVERSATIONAL_PRECEDENCE` ровно `['FAREWELL', 'THANKS', 'GREETING']`.
- GREETING: `здравствуйте` → `GREETING`; `добрый день` (биграмма) → `GREETING`.
- FAREWELL: `до свидания` → `FAREWELL`.
- THANKS: `спасибо` → `THANKS`; `спасибо большое` (биграмма) → `THANKS`.
- Смешанные: `спасибо до свидания` → `FAREWELL` (приоритет прощания над благодарностью — кейс 11).
- Приоритет благодарности над приветствием: `здравствуйте спасибо` → `THANKS`.
- Нет маркеров: `записаться к врачу` → `null`.
- `алё` → `null` (кейс 10).
- Детерминизм: одинаковый вход → одинаковый результат (`deepStrictEqual` по двум вызовам).

**Реализация:** собрать множества маркеров по классам (униграммы+биграммы); проверить членство токенов в каждом множестве; по `CONVERSATIONAL_PRECEDENCE` вернуть первый класс, у которого есть совпадение; иначе `null`. #### Шаг 5.1 — `classify.js` + `classify.test.js`

**Файлы (создать):**

**Контракт (см. `architecture.md` «`classify(text) → result`» + «Контракт публичного API» + «Инварианты»; `pipeline.md` все этапы; `roadmap.md` §2 + §7 шаг 9):**

```
classify(text) → {
  intent:     'BOOK'|'CANCEL'|'RESCHEDULE'|'INFO'|'OPERATOR'|'COMPLAINT'|'GREETING'|'FAREWELL'|'THANKS'|'UNCLEAR',
  confidence: number,   // 0..1
  scores:     { BOOK, CANCEL, RESCHEDULE, INFO, OPERATOR, COMPLAINT },   // сырые взвешенные скоры (только доменные)
  matched:    { BOOK: [...], CANCEL: [...], RESCHEDULE: [...], INFO: [...], OPERATOR: [...], COMPLAINT: [...] }
}
```

**Пайплайн (точно по `architecture.md` «`classify(text) → result`» 7 шагов и `pipeline.md` этапы 1–8):**
1. `normalized = normalize(text)`; если `null` (guard-fail) → вернуть `UNCLEAR` с `confidence: 0`, `scores` все 0, `matched` пустые.
2. `tokens = tokenize(normalized)`.
3. `conversation = detectConversation(tokens)` — конверсационный кандидат.
4. `{ scores, matched } = score(tokens, INTENTS)`.
5. Если `max(scores.values()) < fallbackThreshold` → слить `fuzzy(tokens, INTENTS, THRESHOLDS)` в `scores`/`matched` (дельты прибавляются, `matched`-массивы конкатенируются).
6. **Резолвинг (двухуровневый, `pipeline.md` «Этап 7»):**
   - **Уровень 1 — доменный:** для каждого доменного намерения `confidence_i = clamp(score_i / referenceScore_i, 0, 1)`; выбрать `top1` (макс `confidence`) и `top2` (второй по величине). Если `confidence_top1 ≥ minConfidence` И `confidence_top1 − confidence_top2 ≥ ambiguityGap` → `intent = top1`, `confidence = confidence_top1`.
   - **Уровень 2 — конверсационный:** иначе если `max(scores) < domainSilenceThreshold` И `conversation ≠ null` → `intent = conversation`, `confidence = conversationalConfidence`.
   - **Уровень 3 — иначе** → `intent = 'UNCLEAR'`, `confidence = confidence_top1` (лучшая отвергнутая), `scores`/`matched` заполнены тем, что сработало.
7. Собрать и вернуть `{ intent, confidence, scores, matched }`.

**Инварианты (`architecture.md` «Инварианты»):** `classify` — чистая функция; никогда не бросает исключение (любой не-строковый/`null`/`undefined` вход → `UNCLEAR`); `intent` всегда одна из 10 строк; ключи `scores` ровно 6 доменных; `confidence ∈ [0, 1]`.

**Тесты сначала (ключевые кейсы; полный список — `test-strategy.md` «`classify.test.js`»):**
- Guard-путь: `null`, `undefined`, `''`, `'   '`, `'ок'` (короткая) → `intent: 'UNCLEAR'`, `confidence: 0`, все скоры 0.
- Строгий `minConfidence`: вход с одним слабым доменным сигналом ниже порога → `UNCLEAR` (синтетический кейс: только `запись` → все скоры ≈0.3 → `confidence` ≈0.05 < `minConfidence` → `UNCLEAR`).
- `ambiguityGap`: синтетический вход, где два намерения почти равны → `UNCLEAR` (можно mock-нуть `INTENTS` или подобрать вход, дающий двум намерениям близкие скоры).
- Явный доменный победитель: `'мне нужно отменить запись на пятницу'` → `intent: 'CANCEL'`, `confidence ≥ minConfidence`.
- Доменное доминирует над конверсационным: `'здравствуйте хочу записаться к терапевту'` → `BOOK`, **не** `GREETING` (кейс 1).
- Конверсационное при молчащем домене: `'до свидания'` → `FAREWELL`; `'спасибо'` → `THANKS`; `'здравствуйте'` → `GREETING`.
- Приоритет конверсационных: `'спасибо до свидания'` → `FAREWELL` (кейс 11).
- Форма вывода: `deepStrictEqual` на полной форме `{ intent, confidence, scores, matched }` для одного кейса; ключи `scores` ровно 6 доменных (нет `UNCLEAR`, нет `GREETING`/`FAREWELL`/`THANKS`).
- `confidence ∈ [0, 1]`: для нескольких входов `assert.ok(result.confidence >= 0 && result.confidence <= 1)`.
- Детерминизм: два вызова `classify('...')` с одинаковым входом → `deepStrictEqual` результатов.
- Никогда не бросает: обернуть вызовы с `null`/`undefined`/`{}`/`42`/`Symbol()`/очень длинной строкой в `assert.doesNotThrow(() => classify(...))`.

#### Шаг 6.3 — Настройка: испорченные кейсы 5–9

**Кейс 8 (OPERATOR, перевёрнутый порядок) — начать с него, самый устойчивый:**
- Ожидание: `с человеком`(3.0) + `человеком`(2.0) + `роботом`(2.0) ≈ 7.0; OPERATOR `referenceScore` ≈6.0 → 1.0 → **OPERATOR**.

**Кейс 5 (BOOK, STT-разрыв `за писаться`):**
- Ожидание: только биграмма `за писаться`(3.0) → BOOK = 3.0. `confidence = 3.0 / referenceScore_BOOK`. Нужно `≥ minConfidence` (0.35) → `referenceScore_BOOK ≤ 3.0/0.35 ≈ 8.57`. При `referenceScore_BOOK = 6.0` → `confidence = 0.5` ✓.

**Кейс 6 (CANCEL, слова-паразиты ломают биграмму):**
- Ожидание: паразиты ломают `отменить запись`, остаётся только униграмма `отменить`(2.0) → CANCEL = 2.0. `confidence = 2.0 / referenceScore_CANCEL`. Нужно `≥ 0.35` → `referenceScore_CANCEL ≤ 2.0/0.35 ≈ 5.71`. При `referenceScore_CANCEL = 5.0` → `confidence = 0.4` ✓ (на грани).
- Фаззи срабатывает (max 2.0 < `fallbackThreshold` 3.0), но `отменить` совпал точно → пропущен; `запись` слабая; `наверное`/`это`/`самое` — не близко к словарю → дельта ≈0.

- Если падает в UNCLEAR по `minConfidence`: **понизить** `referenceScore_CANCEL` до 5.0 (если ещё выше) или до 4.5. Следить, чтобы чистый кейс 2 не потерял дискриминацию (при `referenceScore_CANCEL = 4.5` кейс 2 даёт `5.0/4.5 ≈ 1.11` → clamped 1.0 — ок).

**Кейс 7 (INFO, `скока` не нормализуется):**
- Ожидание: только униграмма `стоит`(2.0) → INFO = 2.0. `confidence = 2.0 / referenceScore_INFO`. Нужно `≥ 0.35` → `referenceScore_INFO ≤ 2.0/0.35 ≈ 5.71`. При `referenceScore_INFO = 6.0` → `confidence = 0.33` ✗ **на грани/падает**.

- **Решение настройки:** либо (A) **понизить** `referenceScore_INFO` до 5.5 (тогда `2.0/5.5 ≈ 0.36` проходит и без фаззи — робустнее), либо (B) положиться на фаззи (хрупче: зависит от `fuzzyMinPartial`). **Рекомендация A** — `intent-vocabulary.md` кейс 7 явно: «`стоит` одна должна очищать `minConfidence`; фаззи `скока`≈`сколько` — бонус, не требуется». Понизить `referenceScore_INFO` до 5.5. Проверить, что чистый кейс 3 остаётся clamped 1.0 (`10.0/5.5 ≈ 1.82` → 1.0 ✓).

**Кейс 9 (RESCHEDULE, фонетическая путаница `принести` — витрина принципов):**
