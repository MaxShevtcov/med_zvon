# Стратегия тестирования — МедЗвон

**Раскрывает:** `roadmap.md` §8
**Цель:** полный список юнит-тестов по модулям, спецификация приёмочного гейта, краевые случаи и соглашения по запуску.

---

## Подход

- **TDD** на всём пути: Red → Green → Refactor. Тест пишется до реализации.
- **Юнит-тесты** рядом с каждым модулем: `src/<module>.js` → `src/<module>.test.js`.
- **Приёмочный гейт** — `src/examples.test.js`: все 11 примеров брифа, таблично-управляемый, один тест на кейс. Гейт должен быть зелёным для сдачи.
- **Раннер:** `node --test` (все `*.test.js`); отдельный файл `node --test src/foo.test.js`; watch `node --test --watch`.
- **Импорты:** `import test from 'node:test'`; `import assert from 'node:assert/strict'`; равенство объектов через `assert.deepStrictEqual`.
- **Детерминизм:** без времени/сети в тестах; моки `node:test` не ожидаются (нет I/O).

## Юнит-тесты по модулям

### `thresholds.test.js`

- Все константы экспортируются и являются числами.
- Каждая в разумном диапазоне:
  - `0 < guardMinLength ≤ maxInputLen`
  - `0 < minConfidence ≤ 1`
  - `0 ≤ ambiguityGap ≤ 1`
  - `fallbackThreshold > 0`
  - `minTokenLenForFuzzy ≥ 1`
- Веса согласованы: `strongBigramWeight > mediumUnigramWeight > weakUnigramWeight`.
- Константы заморожены (не мутируются при попытке записи) — если используется `Object.freeze`.

### `normalize.test.js`

`normalize(text)` → строка или guard-сентинел (`null`).

- Guard-отказ (`null`):
  - `null`, `undefined`
  - `''` (пустая строка)
  - `'   '` (только пробелы)
  - строка короче `guardMinLength` после trim (например, `'ок'`)
- Успешная нормализация (строки):
  - приведение к нижнему регистру: `'Приём'` → `'приём'`
  - очистка пунктуации: `'приём,'` → `'приём'`
  - схлопывание пробелов: `'а   б'` → `'а б'`
  - trim краёв
  - ограничение длины: вход длиннее `maxInputLen` обрезается
- Не-строка → guard-отказ (например, `42`, `{}`).
- Идемпотентность: `normalize(normalize(x)) === normalize(x)` для чистого входа.
- Чистота: входная строка не мутируется.

### `tokenize.test.js`

`tokenize(normalized)` → `{ unigrams: string[], bigrams: string[] }`.

- Униграммы: `'хочу за писаться'` → `['хочу', 'за', 'писаться']`.
- Биграммы: соседние пары, соединённые пробелом: `['хочу за', 'за писаться']`.
- Пустая строка → `{ unigrams: [], bigrams: [] }`.
- Один токен → одна униграмма, `bigrams: []`.
- Два токена → одна биграмма.
- Вход не мутируется.

### `conversational.test.js`

`detectConversation(tokens)` → `GREETING` / `FAREWELL` / `THANKS` / `null`.

- Приветствие распознаётся: `здравствуйте` → `GREETING`; `добрый день` (биграмма) → `GREETING`.
- Прощание: `до свидания` → `FAREWELL`.
- Благодарность: `спасибо` → `THANKS`; `спасибо большое` (биграмма) → `THANKS`.
- Смешанные маркеры: `спасибо до свидания` → `FAREWELL` (приоритет прощания над благодарностью).
- Приоритет благодарности над приветствием: `здравствуйте спасибо` → `THANKS`.
- Отсутствие маркеров: `записаться к врачу` → `null`.
- «алё»/«ало» НЕ являются маркерами: `алё` → `null`.
- Детерминизм: одинаковый вход → одинаковый результат.

### `intents.test.js`

Проверка инвариантов структуры `INTENTS`:

- Есть все 6 доменных намерений (`BOOK`, `CANCEL`, `RESCHEDULE`, `INFO`, `OPERATOR`, `COMPLAINT`) и `UNCLEAR`.
- У каждого скоримого намерения есть `unigrams`, `bigrams` (массивы `{ token, weight }`) и числовой `referenceScore`.
- У `UNCLEAR` пустые `unigrams` и `bigrams`.
- Ни один токен не является **сильным** сигналом (вес ≥ `mediumUnigramWeight`) более чем в одном намерении — особенно `запись` слабая (≤ `weakUnigramWeight`) везде, где встречается.
- Ни одна сильная биграмма не повторяется как сильная биграмма в другом намерении.
- Веса берутся из констант `thresholds.js` (нет встроенных magic numbers).
- Все токены записей — в нижнем регистре и без пунктуации.

### `score.test.js`

`score(tokens, intents)` → `{ scores, matched }`.

- Вес биграммы > веса униграммы: фраза даёт больше скора, чем одиночное слово.
- Только точное совпадение: токен `за писаться` совпадает с биграммой `за писаться`, но НЕ с униграммой `записаться`.
- Одиночная `запись` даёт ≈0 для BOOK и не побивает `отменить запись` у CANCEL (регрессия на ничью BOOK/CANCEL).
- `matched` перечисляет сработавшие строки записей по намерениям.
- Отсутствие совпадений → все скоры 0, `matched` пуст.
- Пустые токены → все скоры 0.

### `fuzzy.test.js`

`fuzzy(tokens, intents, thresholds)` → частичные добавки `{ scores, matched }`.

- `принести` против `перенести` даёт частичный вес RESCHEDULE (> 0).
- Короткие токены (`< minTokenLenForFuzzy`) пропускаются (вес 0).
- Точно совпавшие токены не пере-скориваются (нет двойного счёта).
- Токен без близкого соседа в словаре → добавка 0.
- Левенштейн корректен на известных парах (например, расстояние между `принести` и `перенести` ожидаемо мало; `кот` и `собака` — велико).
- Выход — дельта, а не полный скор (сумма `score + fuzzy` корректна в `classify`).

### `classify.test.js`

Оркестратор + двухуровневый резолвер:

- Guard-путь: `null`/`undefined`/`''`/короткая строка → `intent: 'UNCLEAR'`.
- Строгий `minConfidence`: слабый одинокий доменный сигнал → `UNCLEAR`.
- `ambiguityGap`: почти-ничья двух доменных намерений → `UNCLEAR`.
- Явный доменный победитель → топ-намерение.
- Доменное доминирует над конверсационным: `здравствуйте хочу записаться` → `BOOK`, а не `GREETING`.
- Конверсационное при молчащем домене: `до свидания` → `FAREWELL`; `спасибо` → `THANKS`.
- Приоритет конверсационных: `спасибо до свидания` → `FAREWELL`.
- Форма вывода: `{ intent, confidence, scores, matched }`, ключи `scores` — ровно 6 доменных намерений (без `UNCLEAR` и без конверсационных).
- `confidence ∈ [0, 1]`.
- Детерминизм: одинаковый вход → глубоко равный (`deepStrictEqual`) вывод между вызовами.
- Никогда не бросает исключение на любом входе.

### `index.test.js`

- `import { classify } from './index.js'` работает.
- Сигнатура стабильна: `classify` — функция, возвращает объект нужной формы.

## Приёмочный гейт — `src/examples.test.js`

Таблично-управляемый: массив `{ input, expected }` и по одному тесту на кейс. Это финальная проверка, где идёт настройка порогов/весов (шаг 9 роадмапа).

| # | Текст STT | Ожидаемое намерение |
|---|-----------|---------------------|
| 1 | «здравствуйте хочу записаться к терапевту на завтра» | BOOK |
| 2 | «мне нужно отменить запись на пятницу» | CANCEL |
| 3 | «скажите сколько стоит приём кардиолога» | INFO |
| 4 | «это безобразие я час жду на линии хочу пожаловаться» | COMPLAINT |
| 5 | «хочу за писаться к врачу на вторник» | BOOK |
| 6 | «мне ну это самое отменить наверное запись» | CANCEL |
| 7 | «скока стоит прием у лора» | INFO |
| 8 | «хочу с человеком поговорить а не с роботом» | OPERATOR |
| 9 | «принести запись на среду вместо четверга» | RESCHEDULE |
| 10 | «ыаыы ало алё» | UNCLEAR |
| 11 | «спасибо до свидания» | FAREWELL |

Дополнительные проверки гейта:

- Кейс 9: `принести` **без** `вместо` (например, «принести справку в клинику») → `UNCLEAR` (двусмысленный токен не решает один).
- Кейс 1: маркер приветствия не перебивает доменное намерение (`здравствуйте` + `BOOK` → `BOOK`).
- Чистые конверсационные: «здравствуйте» → `GREETING`, «до свидания» → `FAREWELL`, «спасибо большое» → `THANKS`.
- Нет ложного `UNCLEAR` на кейсах 1–9 и 11; нет ложного намерения на 10.
- Детерминизм: перезапуск дважды — идентичные результаты.

## Краевые случаи (общий список)

- `null` / `undefined` / пустая строка / только пробелы / не-строка.
- Очень длинный вход (лимит `maxInputLen` срабатывает, не падая).
- Только пунктуация (например, `'?!...'`).
- Смешанный регистр.
- STT-порча:
  - разрывы слов (`за писаться`);
  - фонетические подмены (`принести` ↔ `перенести`);
  - слова-паразиты (`ну`, `это самое`, `наверное`);
  - разговорные формы (`скока`);
  - бессмыслица (`ыаыы ало алё`).
- Чистое конверсационное высказывание:
  - приветствие (`здравствуйте`);
  - прощание (`до свидания`);
  - благодарность (`спасибо большое`);
  - смешанное (`спасибо до свидания` → `FAREWELL`).
- Повторные вызовы — детерминизм.
- Отсутствие throw на любом входе.

---

## Критерии готовности тестов

- `node --test` полностью зелёный, включая все 11 примеров брифа.
- Уверенность чистых кейсов (1–4) заметно выше `minConfidence`.
- Кейсы 5–9 (испорченные) разрешаются корректно без ложных `UNCLEAR`.
- Кейс 10 — `UNCLEAR` со всеми скорами 0.
- Кейс 11 — `FAREWELL` (приоритет прощания над благодарностью).
- Детерминизм проверен повторным прогоном.
- Нет I/O, сетевых вызовов и временных зависимостей в тестах.
